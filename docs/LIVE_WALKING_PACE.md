# 실시간 도보 페이스 안내

## 범위와 재사용

G9의 `liveNavigationManager`와 `liveNavigationAnalysis`를 일반 도보와 첫 승차 접근 도보에서 공통 사용한다. G2의 `subscribeGps`를 구독하며 별도 `watchPosition`, 기록 세션, 학습 모델, DB 테이블을 만들지 않는다.

- G2 원본 수집·IndexedDB 저장·Supabase 동기화는 그대로다.
- G6 사후 분석과 G7 `recency-weighted-v1`은 수정하지 않는다.
- 기존 `selectWalkingSpeedProfile`로 준비된 G7 또는 기본속도를 선택하고 안내 시작 시 고정한다.
- G8 정적 ETA, 카카오 전체 ETA, T2-3/T2-4A, 참고 도보 지도선은 변경하지 않는다.

## 현재 속도와 페이스

기존 G9 정책을 재사용한다. 정확도 50m 이내, 관측 간격 10초 이내, 좌표 이동속도 3.5m/s 이하를 사용한다. G6처럼 좌표 도약을 먼저 제외한 뒤 유효한 장치 속도를 우선 사용하고, 없으면 좌표 거리/시간을 사용한다. 최근 20초의 연속 구간 중앙값으로 흔들림을 줄인다. 0.35m/s 이하 3개는 정지, 0.7m/s 이상 3개는 이동이며 그 사이는 판정 불가다.

이동 판정 이후 10초 유지 및 최소 5구간을 충족해야 현재 보행속도를 표시하고 ETA에 반영한다. 그 전에는 속도 확인 중과 평소/기본속도 기준 ETA를 표시한다. 정지는 느린 보행으로 분류하지 않는다.

페이스 비교는 G7(없으면 기본속도) 대비 ±15%다. 느림/빠름 상태는 차이가 10% 안으로 돌아와야 해제되는 완충 규칙을 사용한다. 수치는 `liveNavigationConfig.ts`에 있다. GPS 불안정·정지·수신 중단 때 페이스 비교를 보류한다. 학습 전 사용자는 기본속도 기준임을 표시한다.

## 남은 도보 ETA

- 실제 G8 polyline에 현재 위치를 투영하여 경로상의 남은 거리를 사용한다. 직선거리를 남은 경로로 만들지 않는다.
- 기존 G9 혼합속도: 최근 안정 속도 60% + 평소/기본 속도 40%.
- 원시 남은 시간: 남은 경로거리 / 적용속도. 5초 간격, 새 GPS가 있을 때 재평가하며 기존 smoothing alpha 0.35를 사용한다.
- 이동 중 표시 시간은 1초 간격으로 갱신하고 정지 중에는 임의 이동거리를 만들지 않는다. 정지 후에는 평소/기본속도로 돌아간다.
- 60m 경로 이탈 시 ETA 표시를 보류한다. 일반 도보의 기존 제한된 재탐색은 유지한다. 첫 승차 구간은 새 재탐색 요청을 추가하지 않는다.
- 20초간 유효 GPS가 없으면 실시간 속도·ETA를 숨긴다. 동일 timestamp GPS는 수신 신선도를 늘리지 않는다.
- 화면 숨김 시 실시간 판정을 보류하고 복귀 후 새 GPS로 속도 관측을 다시 쌓는다. 숨겨진 동안의 이동 경로를 생성하지 않는다.

첫 승차 참고 G8은 연결 미확정 표시를 유지한다. G8 자체가 없으면 실시간 보행 ETA를 만들지 않고 기존 GPS 기록·수동 종료를 제공한다. 출입구 이후 내부 이동 및 신호 대기시간, 대중교통 전체시간은 이 값에 포함하지 않는다.

GPS 자동 종료 목표는 기존 검증된 좌표만 사용한다. 기존 반경 40m·정확도 30m·연속 유효 위치 3회 조건과 중복 방어를 바꾸지 않는다. G9의 속도 품질 기준 50m와 자동 종료용 정확도 30m는 역할이 다르다.

## 검증

모의 GPS로 정상 속도, 좌표 도약(정상 장치 속도로 가려지는 경우 포함), 정지, 페이스 완충, 빠름/느림 ETA 차이, 중복 위치, 화면 복귀, 수신 단절, 경로 이탈을 확인한다. 첫 승차 통합 테스트는 실제 G2 관리자와 fake IndexedDB를 사용해 watcher 1개, 기록 저장 1회, 자동 종료, 동기화 대기 상태를 확인한다. 실 Supabase·GPS 현장 검증과 구분한다.

### iPhone Safari 수동 확인

1. 로그인 후 일반 도보 경로를 조회하고 안내 시작: 위치 권한을 허용하고 약 20초 이상 걸으며 현재 속도·G7 속도·페이스·남은 시간을 확인한다.
2. 정지 후 재개: 정지를 느림으로 표시하지 않는지, 재개 후 충분한 관측이 쌓인 뒤 속도가 반영되는지 확인한다.
3. 화면을 잠갔다 복귀: 수신 대기/새 GPS 확인 상태이며 과거 속도가 즉시 재사용되지 않는지 확인한다. 백그라운드 수집은 보장하지 않는다.
4. 대중교통 경로 상세에서 안내 시작: 첫 접근 도보 구간만 표시하는지, 검증된 승차 지점에서 자동 종료·로컬 저장되는지 확인한다.
5. 미확정 탑승 좌표 또는 참고 G8: 연결 미확정 표시, 수동 종료, 저장 결과를 확인한다.
6. 내 보행 기록에서 원본 기록과 기존 서버 동기화 상태를 별도로 확인한다.

실제 iPhone GPS 이동 테스트, 도로 환경의 속도 정확도 및 Safari 레이아웃은 별도 확인이 필요하다. 새로운 외부 API 호출은 추가하지 않는다.
