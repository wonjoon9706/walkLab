# Egress 복수 후보의 참고 도보

## 변경 조건

`automaticTransitEgress.ts`의 BUS `MULTIPLE_VEHICLE_OPTIONS`와 `MULTIPLE_VERIFIED_BUS_STOPS` 조기 반환을 공통 참고 도보 처리로 연결했다.
기존 정류장 이름/120m 거리/노선/경유 순서 검증 및 `stopId:routeId` 중복 제거는 변경하지 않았다. `reason`과 `MULTIPLE_CANDIDATES` 진단을 그대로 유지한다.

`busAmbiguity`에 차량 수, 후보 조합 수, 고유 정류장 ID 수, 고유 노선 ID 수, 위치 관계, 참고 끝점 근거를 보존한다.
개발 진단은 공통 코드뿐 아니라 원본 reason과 후보별 정류장/노선 ID도 표시한다. 인증키·JWT·사용자 좌표는 추가로 표시하지 않는다.

## 공통 위치 판단

- 같은 step의 `vehicles`는 그 step의 공통 `stops/path`에 속하는 옵션으로 해석한다. 후보가 0~1개라면 유효한 단일 원본 BUS 끝점까지 참고 도보를 허용한다.
- 복수 후보 위치의 모든 쌍이 **5m 이내**면 같은 참고 위치 범위로 처리한다. 정류장 ID 하나/여러 개는 진단에서 별도로 구분한다.
- 서로 다른 위치여도 모든 후보가 원본 BUS 끝점 **5m 이내**면 그 공통 끝점까지의 참고 도보를 허용한다.
- 위 근거가 없으면 `not_established`로 기록하고 G8을 요청하지 않는다.
- 5m는 기존 거리 함수로 비교하는 **참고 위치 허용 오차**다. 실제 정류장 동일성이나 승하차 가능성을 확정하는 규칙이 아니다. 30m G8 스냅 검증은 그대로 유지한다.
- 평균 좌표나 새로운 출입구를 만들지 않는다. 사용 좌표는 언제나 원본 BUS polyline의 마지막 좌표다.

## 기존 기능 재사용과 안전성

`transitPathReferenceWalk.ts`에 명시적 Egress 공통 끝점 옵션만 추가했다. 이 옵션이 없거나 scope가 Access이면 기존 복수 차량 제한이 유지된다.
빈/비정상 원본 좌표, 구간 이름·차량 정보 부족, 취소, 유효 G8 polyline 부재는 기존처럼 제외한다.

성공 결과는 `referenceWalk`에만 보존한다. `ready` 하차 위치로 바꾸거나 후보 하나를 임의 선택하지 않는다.
기존 점선 지도선과 `부분 개인화 참고` 계산 경로를 그대로 사용하며 G7/G8 계산식은 변경하지 않았다.
미확인 연결 구간을 직선으로 추가하지 않는다.

참고 하차 좌표는 GPS 자동 종료 목표로 사용하지 않는다. 자동 종료는 기존 Access의 검증된 목표만 사용한다.
40m/정확도 30m/신규 GPS 3회, 저장·동기화/G2/G6/G7/DB는 변경하지 않았다. 서울시 API와 3개 카드·더보기도 유지한다.

## 검증

비식별 Mock으로 다음을 검증한다.

- 동일 정류장에 복수 차량, 동일 ID의 복수 노선, 서로 다른 ID의 일치/근접 위치
- 서로 다른 위치에 공통 끝점 근거가 없을 때 G8 미호출
- 공통 원본 끝점의 유효성 검사와 Access 제한 유지
- 실제 Egress 결정 결과를 UI에 전달해 참고 지도선·부분 ETA·목록/상세 시간 일치 확인
- 참고 하차 도보만 존재할 때 안내 시작의 GPS 목표가 null인지 확인

외부 API·실제 브라우저 이동은 검증하지 않았다. 사용자 실제 경로의 후보 위치가 위 공통 위치 조건을 충족하지 않으면 계속 미확정이다.
commit/push/merge/배포는 수행하지 않는다.
